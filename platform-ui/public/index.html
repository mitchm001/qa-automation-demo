    About this project

    This event sign-up app is a small, real application built to be tested. It has a capacity limit, a waitlist, duplicate checks and a login, which give an automated test suite meaningful rules to verify.

    What it demonstrates

    • Layered testing with Playwright + TypeScript: unit, API, UI, hybrid (API and UI together), security and auth suites, each in its own project.
    • API testing: status codes, validation with boundary values, create/read/update/delete checks, business rules and response schemas.
    • UI testing with Page Objects: real user flows, field errors, pop-ups, and role- and label-based locators.
    • Race conditions: simultaneous sign-ups prove the event never goes over capacity, verified to fail when the server's locking is removed.
    • Security checks: HTML and SQL-like input, ignored extra fields, security headers, error responses that leak nothing.
    • Auth: login and logout, 401s on every protected request, secure session cookies, and one saved login reused across the suite.
    • QA practice: written test cases with priorities and traceability, network-failure mocking, and real bugs logged with skipped tests that document the fix.
